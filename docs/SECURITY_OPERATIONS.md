# 보안 운영 설정

## 현재 공개 편집 모델

- 공개 회원가입과 인재풀 등록은 종료 상태이며 관련 API는 `410 Gone`을 반환한다.
- 공지·논문·모집요강은 로그인 없이 누구나 등록·수정·삭제할 수 있다.
- 관리자 로그인·로그아웃·관리자 메뉴는 활성 클라이언트 화면에서 제거했고 `/admin`은 모집요강으로 이동한다.
- 논문 댓글 수·목록·작성 UI는 제거했으며 논문 댓글 쓰기 API는 `410 Gone`을 반환한다. 기존 댓글 데이터와 스키마는 삭제하지 않는다.
- 기존 관리자 인증·부트스트랩·계정 데이터는 롤백 안전을 위해 서버에 보존하지만 현재 공개 콘텐츠 편집에는 사용하지 않는다.

로그인 없는 공개 수정·삭제는 방문자 식별과 복구 권한을 제공하지 않는다. 동일 출처 검사와 속도 제한은 자동화된 남용을 줄일 뿐, 승인된 편집자만 구분하는 접근통제가 아니다.

## 공개 쓰기 통제

- 모든 `/api` 쓰기 요청에 동일 출처 검사를 적용한다. 프로덕션에서 `Origin`이 없거나 허용 목록과 다르면 403으로 거부한다.
- 공지·논문·모집요강의 POST/PATCH/DELETE는 IP 기준 15분에 30회로 제한한다.
- 제목·본문·날짜·기관·URL은 Zod 스키마로 길이와 형식을 검증한다.
- 삭제 전에 클라이언트 확인 대화상자를 표시하고, 저장·삭제 중에는 중복 요청과 모달 닫기를 막는다.
- 감사 로그에는 요청 ID, 동작과 대상 ID만 기록하며 본문·첨부 내용·비밀번호를 기록하지 않는다.

## 공개 첨부파일

- 공지 첨부 업로드는 IP 기준 15분에 5회, 다운로드는 15분에 120회로 제한한다.
- 한 번에 최대 5개, 파일당 10MB이며 허용 확장자·MIME·파일 시그니처를 모두 확인한다.
- 저장 파일명은 무작위 UUID를 사용하고 다운로드 경로는 basename·확장자·읽기 권한을 다시 검증한다.
- 모집요강 첨부는 HTTPS 외부 주소만 허용한다.

현재 첨부는 Render 로컬 파일시스템에 저장되므로 재시작·재배포 시 사라질 수 있다. 장기 운영에는 만료형 공개 URL을 제공하는 객체 저장소로 이전하고 악성 파일 검사와 삭제·보존 정책을 추가한다.

## 보존된 관리자 인증 코어

- PostgreSQL scrypt 관리자 계정, 세션, 부트스트랩과 관리자 관리 API는 데이터 삭제 없이 보존한다.
- 서버 시작 시 부트스트랩 코드를 자동 생성하거나 로그에 출력하지 않는다.
- `/api/admin-bootstrap/status`를 명시적으로 조회해 최초 설정이 필요할 때만 15분 유효 코드가 생성된다.
- 환경 관리자 방식은 `ADMIN_USERNAME`과 유효한 `ADMIN_PASSWORD_HASH`를 함께 설정해야 하며, 해시는 `npm run security:hash-password`의 대화형 TTY 숨김 입력으로만 생성한다.
- 관리 기능을 다시 활성화하려면 별도 승인 작업에서 `/admin` UI·내비게이션·서버 권한 정책을 함께 복원하고 기존 보안 회귀검사를 다시 수행한다.

## 유지되는 공통 보안

- 세션 쿠키는 `httpOnly`, 프로덕션 `secure`, `sameSite=lax`이며 세션 ID 재발급·유휴/절대 만료를 유지한다.
- scrypt 비밀번호 해시, 엄격한 해시 구조 검증과 timing-safe 비교를 유지한다.
- 공개 회원가입·인재풀 API 종료와 민감 API `no-store` 정책을 유지한다.
- CSP, HSTS, 클릭재킹·MIME 스니핑·브라우저 권한 방지 헤더를 유지한다.
- 데이터베이스 TLS 인증서 검증과 최소 요청 로그를 유지한다.

## 배포 후 점검

1. 비로그인 브라우저에서 공지·논문·모집요강의 등록→수정→삭제를 각각 테스트한다.
2. 잘못된 Origin 쓰기 요청이 403, 과도한 요청이 429를 반환하는지 확인한다.
3. 논문 화면에 댓글 관련 문구가 없고 논문 댓글 쓰기 API가 410을 반환하는지 확인한다.
4. `/admin`이 모집요강으로 이동하고 헤더·모바일 메뉴에 관리자 로그인·로그아웃·관리자 메뉴가 없는지 확인한다.
5. 공지 첨부의 허용 파일 업로드·공개 다운로드와 허용되지 않은 파일 거부를 확인한다.
6. `/api/users` 공개 등록과 `/api/talents`가 410을 반환하는지 확인한다.
7. GitHub `main` HEAD와 배포 커밋 SHA가 일치하고 빌드·시작 로그에 자격증명이나 자동 bootstrap 코드가 없는지 확인한다.

## 장애·롤백

- 공개 변조가 발생하면 우선 서비스 쓰기 경로를 차단하고 DB 백업 또는 정상 커밋·데이터로 복구한다.
- 임의로 운영 DB를 삭제하거나 비밀번호·해시·고정 bootstrap 코드를 Git에 추가하지 않는다.
- 관리자 인증 방식으로 되돌릴 때는 보존된 서버 코어를 활용하되, 공개 CRUD 라우트의 limiter를 `adminOnly`로 교체하고 클라이언트 권한 표시·통합테스트를 함께 복원한다.
- 기존 인재풀 테이블은 사용자 승인 없는 데이터 삭제를 피하기 위해 스키마에 보존하고 공개 라우트에서는 계속 종료 상태로 유지한다.
