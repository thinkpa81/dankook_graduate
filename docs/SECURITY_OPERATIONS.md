# 보안 운영 설정

## 현재 인증 모델

- 공개 회원가입과 인재풀 등록은 종료되었으며 관련 API는 `410 Gone`을 반환한다.
- 공개 방문자는 학과 소개, 공지사항, 논문, 내규와 모집요강만 조회한다.
- 공지·논문·모집요강의 등록·수정·삭제, 파일 업로드와 관리자 계정 관리는 `ADMIN` 역할만 수행한다.
- 관리자 비밀번호는 애플리케이션 코드·Git·브라우저 저장소·로그에 평문으로 저장하지 않고 PostgreSQL에 scrypt 해시로만 저장한다.
- 모든 관리자 요청은 세션 역할뿐 아니라 데이터베이스의 현재 계정 상태와 역할을 다시 확인한다.
- 비밀번호 변경 시 계정 인증 버전을 증가시켜 해당 관리자의 기존 로그인 세션을 모두 무효화한다.

## 환경 변수 없이 최초 관리자 설정

활성 관리자 계정과 `ADMIN_USERNAME`/`ADMIN_PASSWORD_HASH`가 모두 없으면 서버가 최초 관리자 설정 모드로 진입한다.

1. 서버 시작 시 256비트 일회성 설정 코드를 생성한다.
2. 코드는 Render 서버 로그의 `admin_bootstrap` JSON 항목에만 출력하며, 공개 상태 API에는 코드 자체를 노출하지 않는다.
3. `/admin`에서 일회성 코드, 관리자 아이디, 표시 이름과 비밀번호를 입력한다.
4. 코드는 15분 동안만 유효하며 최초 관리자 생성 직후 메모리에서 폐기된다.
5. 비밀번호는 요청 처리 중 즉시 scrypt 해시로 변환해 저장하며 원문은 응답·감사 로그에 남기지 않는다.

코드가 만료되면 `/api/admin-bootstrap/status`를 다시 조회하거나 서비스를 재시작해 새 로그 항목을 확인한다. 최초 관리자가 생성된 뒤에는 설정 API가 `409`로 차단된다.

## 선택 환경 변수

- `PUBLIC_ORIGIN`: 권장값 `https://dankook-graduate.onrender.com`. 동일 출처 검증 기준이다.
- `SESSION_SECRET`: 선택 항목. 32바이트 이상의 예측 불가능한 값을 설정하면 재시작 후에도 세션 서명을 유지하기 쉽다.
- `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`: 선택적 비상 관리자 방식. 둘을 반드시 함께 설정하며 해시는 `npm run security:hash-password`로 생성한다.

해시 생성 명령은 대화형 터미널(TTY)에서 비밀번호와 확인값을 화면에 표시하지 않고 입력받는다. 파이프·리디렉션·명령행 인수로 비밀번호를 전달하는 방식은 거부한다. 생성된 해시는 Render Secret에만 저장하며 문서·Git·이슈·로그에 복사하지 않는다.

`SESSION_SECRET`을 설정하지 않으면 서버가 시작할 때 384비트 임시 난수를 생성한다. 난수는 저장소·로그·클라이언트에 노출되지 않지만 서비스 재시작 시 기존 로그인 세션이 만료된다.

## 관리자 계정 운영

1. 최초 설정을 완료한 관리자는 `/admin`에서 다른 관리자 계정을 추가한다.
2. 관리자가 비밀번호를 변경하면 새 값은 scrypt 해시로 교체된다.
3. 현재 로그인한 계정은 스스로 삭제할 수 없다.
4. 데이터베이스 트랜잭션과 advisory lock으로 마지막 활성 관리자 삭제를 차단한다.
5. 관리자가 삭제·중지되면 기존 세션이 남아 있어도 다음 관리자 요청에서 즉시 거부된다.
6. 관리자 목록 API는 비밀번호·해시·이메일을 반환하지 않는다.

## 적용된 통제

- PostgreSQL 영속 세션, 30분 유휴 만료와 8시간 절대 만료
- 로그인 성공 시 세션 ID 재발급, `httpOnly`·프로덕션 `secure`·`sameSite=lax` 쿠키
- 동일 출처 검증, 로그인·초기 설정·댓글·조회·업로드 요청 속도 제한
- 공지·논문·모집요강·관리자 변경 API의 서버 역할 검증
- scrypt 비밀번호 해시와 기존 평문 비밀번호 자동 무효화
- 공개 회원가입·인재풀 API 종료 및 민감 응답 캐시 금지
- 요청·응답 본문을 제외한 요청 식별자 기반 최소 로그와 관리자 작업 감사 로그
- 업로드 확장자·MIME·파일 시그니처·개수·크기 검증, 무작위 저장명, 관리자 인증 다운로드
- 모집요강 외부 첨부 주소의 HTTPS 강제
- 데이터베이스 TLS 인증서 검증과 엄격한 scrypt 해시 구조 검증
- CSP, HSTS, 클릭재킹·MIME 스니핑·브라우저 권한 방지 헤더

## 배포 후 점검

GitHub Actions와 Render는 Node.js 24를 사용하고, Render는 `main` 브랜치의 GitHub 검사 통과 커밋만 자동 배포한다.

1. `/api/admin-bootstrap/status`에서 최초 관리자 설정 필요 여부를 확인한다.
2. 필요한 경우 Render 로그의 최신 `admin_bootstrap` 코드를 15분 안에 `/admin`에서 사용한다.
3. 관리자 로그인 후 모집요강 등록·수정·삭제와 관리자 추가·비밀번호 변경·삭제를 확인한다.
4. 비로그인 상태에서 관리자 쓰기 API가 401, 일반 비관리자 세션이 403을 받는지 확인한다.
5. `/api/users` 공개 등록과 `/api/talents`가 410을 반환하는지 확인한다.
6. 관리자 목록과 브라우저 네트워크 응답에 비밀번호·해시·이메일이 없는지 확인한다.
7. GitHub `main` HEAD와 Render 배포 커밋 SHA가 일치하고 빌드·시작 로그에 자격증명이 없는지 확인한다.

## 운영상 유의사항

현재 업로드 파일은 애플리케이션의 비공개 경로에서 관리자 인증 후 제공된다. Render의 로컬 디스크는 영구 객체 저장소가 아니므로, 장기 운영 시에는 동일한 관리자 권한 검사를 유지한 채 비공개 객체 저장소와 만료형 다운로드 URL로 이전한다.

기존 인재풀 테이블은 사용자 승인 없는 데이터 삭제를 피하기 위해 스키마에 보존하되 공개 라우트에서 접근할 수 없도록 종료 상태로 유지한다.

비상 환경변수 관리자의 해시를 교체할 때는 기존 PostgreSQL 세션이 남지 않도록 `SESSION_SECRET`도 회전하거나 세션 저장소를 운영 절차에 따라 무효화한다. 데이터베이스 관리자 계정은 `authVersion` 증가로 기존 세션이 자동 무효화된다.
